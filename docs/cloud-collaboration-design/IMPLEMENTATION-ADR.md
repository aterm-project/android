# Implementation ADR — cloud collaboration (2026-11-08)

Status: **implemented** for the default SQLite deployment. The other files in
this directory are the reviewed *proposal*; this ADR records what was built
and where real code required a deviation. Operator guide: `docs/CLOUD-SHARING.md`.

## Baselines

* Client/packages/protocol: immutable reviewed baseline `3d98a6c`.
* Server/deploy/integration: verbatim import of published `aterm-project/server`
  `b0ccc80` as commit `b777fcf` (accepted second baseline, coordinator R2.1).

## Decisions

| # | Decision | Proposal delta / reason |
| --- | --- | --- |
| A1 | SQLite only. In the PostgreSQL sync-core runtime cloud routes are not registered, no capability is advertised and `pg_sync_route_is_supported` keeps them closed (test). | Explicit fail-closed instead of a partial PG path. |
| A2 | `CloudConfig` lives in `AppState.cloud`, not in `Config`. Absent setting → documented default; present but malformed → config error, feature closed and unadvertised. | Narrow merge surface; R3. |
| A3 | Gateway key: X25519 via RustCrypto `crypto_box` 0.9 `seal` (libsodium-compatible sealed box). Key file 0600, refused inside `ATERMIUS_DATA_DIR` (never in backups); public key + key ID signed by the instance Ed25519 key; clients verify against the pinned instance key. Interop proven both ways by `protocol/test-vectors/share-gateway-v1.json` (libsodium→Rust, Rust→Dart sodium, Dart-signed capsule→Rust). | As proposed; R2.5. |
| A4 | Capsule = device-signed JCS header + sealed inner. Server checks signature, Vault owner role, active device, head revision, target policy. Gateway re-checks inner bindings after unseal (`CAPSULE_MISMATCH` revokes the capsule). Guest access additionally requires the **sealer device to be active, owned by the sealer, who is still the active unrestricted Vault owner**, at ticket issue, consumption and every recheck. | R5. |
| A5 | SSH host key: the Vault stores only algorithm + `SHA256:` fingerprint, guacd `host-key` needs a full `known_hosts` entry. The gateway performs public-key **discovery** only (bounded banner/packets/time, KEXINIT limited to the trusted key type; RSA offers only `rsa-sha2-512/256`, never SHA-1), compares the blob's SHA-256 to the pin in constant time, and gives guacd an exact entry for the pinned IP:port; libssh2 then verifies the real host signature. No crypto is implemented by Atermius here. | Real-code constraint; R2.4. |
| A6 | RDP: `cert-fingerprints` from the pinned certificate, `ignore-cert=false`, `security` restricted to `nla`/`tls` (never `any`/`rdp`, which could bypass pinning). Required guacd args missing → fail closed. VNC only with `ATERMIUS_SHARE_VNC_ENABLED=true`. | Tightened; R1. |
| A7 | Links: `/s/<slug>#s1.<secret>`; HKDF redeem token and display key client-side; SHA-256 at rest; XChaCha display envelope opaque to the server. Defaults 24 h, 1 redemption, 1 concurrent; atomic `UPDATE … WHERE redemptions<max` in the same transaction as guest-session creation. | As proposed. |
| A8 | Guest auth domain: `__Host-atermius-guest` (Secure, HttpOnly, SameSite=Strict, Path=/), exact Origin, `X-Atermius-Guest: v1`, `application/json`, `Sec-Fetch-Site` same-origin, Authorization refused; Bearer routes never read the cookie. WS: exact Origin + live cookie session == ticket session + one-use 30 s ticket. Session resume and ticket issue carry the shown link address (`slug`); a cookie for another link gets the uniform `404`, and the guest page refuses any answer for another address. | As proposed; slug binding R6.3. |
| A9 | Revocation: link `authz_revision`/`secret_version` bound into tickets and connections; a watchdog races DNS, host-key discovery, the guacd handshake and the data pump (1 s ticker + broadcast wake-up, 1 s bounded checks failing closed, so a slow authorization check still lands within the 3 s budget). Authorization is rechecked immediately before credentials are sent. Blocked writes are cancelled; the guest is closed (0.5 s bound) before bookkeeping; upstream gets a non-blocking `disconnect` and is dropped. Tested with injected 0.8 s and 2.5 s check delays. | R4.3, R6.4. |
| A10 | Absolute `valid_from`/`expires_at` (half-open, server clock) implemented; **no recurring windows** and no toggle for them. | Guidance: absolute mandatory, recurring optional. |
| A11 | Organizations/teams/invitations as server-visible metadata; invitations are one-time hashed tokens in `/join#o1.<token>`, optionally bound to an existing account. They never create accounts (closed registration, account invitations, MFA and device enrollment unchanged). | R1. |
| A12 | Grants = desired state. Keys reach grantees only via the existing signed device-targeted Vault invitation, created by the key-holding owner after confirming the recipient's self-signed device card fingerprint; the invitation token is sealed to that device. Org admins cannot obtain or distribute keys. | R1/R2. |
| A13 | **Immediate restriction overlay** (`cloud_member_restrictions`): grant-derived members (provenance row created at key delivery) are recomputed with union semantics over all remaining user/team grants in the same transaction as any org/team/grant/attachment change (`none` or `viewer`). Signed manifests and `vault_members` rows are untouched (so manifest/rotation/transfer invariants and old clients keep working). Every Vault *access* predicate honours the overlay: `require_vault*`, sync repository, objects (via helpers), notifications, presence, collaboration, Vault lists (login, list, recovery), mobile push, Vault audit. Capability/manifest/device-directory predicates intentionally keep signed membership. Live sockets close within their existing 2 s polls. Owners may convert a member to direct; cryptographic removal still needs the owner's key rotation (UI button). | R2.3/R4.1; avoids a new `suspended` state that the client manifest validators reject. |
| A14 | **Selected-Host sharing**: "Share only this Host" copies the selected Host plus owner-approved dependencies (jump chain, credential, trusted KnownHost) into a new dedicated Vault; groups are dropped; unresolved references block. Whole-Vault sharing is a separate labelled choice. Temporary links are per-Host capsules and never expose other Hosts. H1/H2 tests: Dart plan test and black-box server test. | R2.2. |
| A15 | Clipboard: guest streams require `clipboard` open → `blob`* → `end` on the same index; orphan/stale/reused indices and per-stream (64 KiB) / per-connection (4 MiB) overflow are protocol violations; view-only always suppresses paste. Output: per-index rebinding on every stream opener (image streams never broken), bounded tracked state and metered allowed copy. | R4.2. |
| A16 | `desktop::parse` rewritten to linear time (it re-validated UTF-8 over the whole remaining buffer per instruction, a CPU-starvation vector for both Web RDP and the gateway). Same framing rules; tests. | Found while fixing R4.3. |
| A18 | **Fenced owner operations**: the client captures account, device, server instance, API client and Vault at the start of each owner operation and re-verifies them before every request (sealing, capsule PUT, link creation, sharing-Vault copies, delivery, role change, removal); selections that do not take effect or are superseded abort; scope identity uses the controller's auth/server and selection-request generations (not IDs alone), so select-away-and-back (A→B→A) also supersedes and is never undone. Controller steps check before dispatch and before committing a response (Vault creation, signed invitation): a response arriving after sign-out, an account/server switch or a newer selection installs nothing (generated key wiped) and is reported as already completed on the server — never as rolled back. Sharing-Vault copies use scope-bound create operations on the new Vault's repository and complete only after a fully synchronized push; membership refreshes are waited out and re-verified. Accepted members' role changes are owner-confirmed and use the existing signed `changeVaultMemberRole` rotation. Real-controller tests against the server binary cover H1/H2, superseded/no-op selection, sign-out during sealing and delivery, and viewer→editor→viewer through UI and service. | R6.1/R6.2. |
| A19 | **Quota charged on admission (G14)**: ticket issuance charges nothing. On `/gateway/v1/connect` the gateway takes an instance slot, then in one serialized write transaction checks the ticket, current authorization and link/session concurrency, atomically charges `max_connections`, consumes the one-use ticket and records the connection. Capacity/concurrency refusals neither consume the ticket nor charge; exhausted/revoked burn the ticket; an admitted attempt counts even if the target or remote login fails later. Served-WS tests: instance cap 1 across two links, `max_concurrent` 1 race between tickets issued while idle, `max_connections` 1 with simultaneous admissions. | R7. |
| A17 | Host-access grants for non-member "connect only" access (proposal P2 §5.3), approval/one-time codes, recurring schedules, adopt, separate gateway process, PG support: **not implemented**, not advertised. | Scope. |
